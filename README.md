# 长春冬日漫游

一个本地运行的长春 2027 冬季城市互动网页。用户从城市游览手册封面进入，第一页制作卡通角色，第二页跟着角色浏览长春及吉林市的 10 座竞赛场馆和 6 处城市景点，抵达后翻开对应地点手记；独立的 `/display` 页面用于展示地图和实时游览统计。

## 启动

需要 Node.js 20 或更新版本。项目没有 npm 依赖。

```powershell
Copy-Item .env.example .env
notepad .env
node server/index.js
```

打开 `.env` 后，选择图像生成渠道并填写对应密钥。例如使用豆包 Seedream：

```dotenv
IMAGE_PROVIDER=doubao
ARK_API_KEY=在火山方舟获取的API密钥
ARK_MODEL=doubao-seedream-5-0-flash-260915,doubao-seedream-5-0-pro-260628
```

此配置先使用 Seedream Flash；只有 Flash 不可用时才尝试 Pro。若只想使用 Flash，可删掉逗号和后面的 Pro 模型。请确认所选模型已在火山方舟账号开通。

保存后运行 `node server/index.js`。打开 `http://localhost:5173/`；在同一台服务器上打开 `http://localhost:5173/display` 可展示大屏。若 `.env` 已存在，保留并编辑现有文件，无需再次复制。服务端配置变更后需要重启 Node 进程。

仓库中的 `.env.example` 只提供空白配置模板，**不包含任何可用 API 密钥**。`.env` 已加入 Git 忽略规则，不会随项目提交；请只在本地 `.env` 中填写密钥，不要将密钥粘贴到源码、README、截图或公开仓库中。无需使用豆包时可保留 `IMAGE_PROVIDER=mock`，该模式不需要密钥。

## 第一次体验

首页有「创建我的冰雪分身」和「直接试玩」两条入口。直接试玩使用浏览器本地绘制的预设角色，翻开手册并进入地图；不会上传照片、调用 `/api/generate` 或使用生图密钥。创建角色则可继续上传或拍摄照片，并使用本机配置的图像生成渠道。

核心路线是：创建或选择角色 → 抵达一个地点 → 阅读地点手记 → 挑战小游戏并收集奖章。场馆或景点只有在角色抵达后才计入本地探索和服务器虚拟到达统计；重复游览不重复增加探索地点数。

地点手记的照片图集支持左右箭头、触屏左右划动、全屏查看，以及图集下方的滑动定位栏。`data/place-gallery.json` 对应 `web/assets/places/` 中的 WebP 照片；用 `node tools/import-place-gallery.mjs <图集 output 目录>` 可重新导入全部照片，再用 `python tools/optimize-place-gallery.py --apply` 压缩图片并更新引用。压缩脚本需要 Pillow；它只清理仓库内重新导入的 JPEG/PNG 副本，原始图集目录不受影响。图集中保留来源及授权状态，原索引标为 `permission-required` 的照片显示“授权待核”。原始索引的 `reviewed`、`photoCaptionVerified` 和 `publishApproved` 均为 false；公开发布前仍须逐张核对照片内容、署名和许可。

封面还可选择「轻松漫游」「冰雪运动挑战」「城市探索之旅」，也可直接跳过。进入地图后点「规划云游路线」，按 30 分钟、1 小时或半天的云游时间和兴趣生成推荐顺序。路线可重排、替换、移除、重新生成，开始后可暂停或退出；角色到达当前站才推进路线。这里的分钟数仅是网页互动体验估时，地图不提供现实道路、交通时间或导航。

「我的冰雪护照」汇总 16 处地点印章、10 枚场馆奖章、知识徽章、个人最佳和当前路线。八个跨地点任务连接探索、运动挑战、观察发现与地点手记，逐项显示完成状态；达成条件后需在护照中领取任务章，同一任务只可领取一次。每处手记给出观察提示、本地挑战、关联任务及下一步；返回地图后保留继续入口。护照中的「制作旅行纪念卡」会在本机生成可下载的图片，含角色、印章进度、代表性成就和日期；不会自动上传或分享照片。游览目标、路线、手记阅读、观察与任务记录保存在原有进度键中，旧进度继续可用。

## 游戏与奖励

场馆挑战包括节奏速滑、冰壶投掷、冰球射门、雪道旗门、越野配速和空中技巧。挑战胜利会获得对应场馆奖章；重玩不会重复发章，个人最佳成绩保存在本地。

地图还有两项独立的加练：冰球门神挑战会给出五次射门轨迹，玩家用左、中、右扑救；冰雪知识快问快答每轮随机抽 5 题，题库有 15 道场馆、冰雪运动与长春景点题目，题序和正确选项位置都会变化，并附逐题说明。答对至少四题会获得知识徽章。它们不会占用十枚场馆奖章。

## 本地进度与隐私

地点探索进度（最多 16 处）、场馆挑战奖章（最多 10 枚）、各场馆最佳成绩、门神扑救纪录和知识徽章分别显示。新版数据保存在 `localStorage` 的 `cc2027:progress:v2`；旧版 `cc2027:progress` 会安全迁移，原键保留不删除。浏览器存储不可用时，本次页面仍可游玩，但进度无法保存。

照片只会在用户主动生成角色时发送给所选图像服务；直接试玩完全离线绘制预设角色。图片生成使用豆包 Seedream。生成失败时不会自动切换模型再次扣费。无需密钥时仍可直接试玩，也可用本地模拟提供商检查生成流程。

## 冰雪角色造型工坊

角色生成页提供 12 种艺术风格、12 种主题、14 类冰雪运动、12 种场景光色氛围、14 套服装，以及发型、头饰、配饰、表情、动作、配色、材质、特效和构图选项。八个造型预设、随机搭配和运动项目推荐会更新同一份配置；配饰最多 3 项，特效最多 2 项，自定义细节最多 240 字。选项保存在原有 `cc2027:creative` 键中，旧版 `vibe/sport/scene/details` 数据会自动兼容。

当前生成流程依靠纯色抠图幕提取完整人物，所以“场景”控制角色环境光与色彩氛围，生成图背景仍为纯色幕；页面会明确说明这一限制，避免把未渲染的背景场景当作预览效果。角色身份保持、照片编辑、直接试玩和现有生图 API 契约均沿用原流程。

## 场馆小游戏

小游戏按赛事项目提供不同操作：短道和速度滑冰考验踩拍节奏；冰壶需要控制投壶力度、路线和碰撞；冰球是观察守门员的点球挑战；雪道游戏要选择旗门路线并躲避雪堆；越野滑雪需要在体力和配速间取舍；空中技巧则包含起跳、空中姿态和平衡控制。每局结束会展示分数和表现，可重试并争取场馆印章。

第六阶段增加十场馆注册表和玩法模式：练习可选轻松、标准或挑战难度；单人排名赛固定标准规则；双人轮流在同一设备上使用相同种子完成两局并比较结果。每局最多 20 秒，事件型玩法会在到时自动结算。短道加入弯道超越，速度滑冰加入分段冲刺，奥林匹克馆点球加入玩家轮流攻防；雪径、平行雪道和高山回转分别调整旗门、路线和障碍指标。开始挑战前可选择模式，游戏中可暂停。随机路线按比赛种子生成，双人赛道可复现。

16 张包内 PNG 精灵放在 `web/assets/games/`，通过 `web/game-assets.js` 按场馆加载；精灵加载失败时仍用 Canvas 程序绘制。排名赛分数、时长、种子和项目指标保存在独立的 `data/game-results.json`，提供 `GET /api/leaderboards`、`GET /api/game-history` 和 `POST /api/game-results`。单项榜按场馆分别排行，十场馆总积分按每馆最高标准赛成绩计算；练习和双人成绩只写入本机历史。五环馆另有跨设备短道模式：房间通过 `POST /api/online-race/rooms` 创建或加入，再由 WebSocket 推送赛况；服务端计时 20 秒并结算选手分数，断线后可在 30 秒内用同一浏览器恢复。两台设备必须访问同一个正在运行且网络可达的服务器，例如同一局域网内使用主机的局域网地址；仅上传代码到 GitHub 不会自动部署成公网服务。联机只传昵称和比赛状态，不使用账号或角色照片。

资源包附带的概念精灵为本项目创作素材，不代表赛事官方资产或官方吉祥物。

六处城市景点也各有一款不参与竞技榜的短彩蛋：伪满皇宫做历史线索梳理、长影旧址排电影节奏、这有山规划停靠路线、南湖记忆冰晶、文化广场观察剪影、长影世纪城完成导演快反。首次完成后，纪念贴纸会单独保存在 `cc2027:attraction-stickers:v1` 并显示在地点手记中，不占十枚场馆奖章。

## 统计说明

`GET /api/places` 提供地图地点。`GET /api/visits` 提供统计快照，`GET /api/visits/stream` 通过 SSE 推送更新，`POST /api/visits` 在角色完成地点到达时记录 `{ placeId, eventId }`。刷新页面、仅查看介绍和跳入地图均不计数。

统计代表本项目中的**虚拟游览到达次数**，并非真实景区客流或去重人数。数据保存于 `data/visits.json`，服务重启后仍保留。单进程内串行写入并使用事件编号防止重试重复计数；局域网设备访问同一服务即可共享。多进程部署需迁移至共享数据库。

地图是冰雪主题城市示意图，概括了相对位置，不提供实际导航。地点介绍中的资料来源可点击查阅。
